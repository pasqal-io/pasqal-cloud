Estimating Memory Consumption and Runtime

The presence of the max_bond_dim and max_krylov_dim config parameters means an upper bound on memory consumption and the complexity of the time evolving algorithm can be estimated. By limiting the max_bond_dim of a simulation to make it fit in the available hardware memory, it can be guaranteed to run for arbitrary times for an arbitrary number of qubits. Of course, the sources of error described on the error page imply that limiting the memory consumption of the program will negatively impact the quality of the results once a certain threshold is exceeded. The page in this link, for example, outlines a case study to determine whether emulation results are accurate.

Estimating the memory consumption of a simulation

Section titled “Estimating the memory consumption of a simulation”

In this section we outline how to estimate the memory consumption of a simulation, for a given max_bond_dim, a Krylov subspace of size max_krylov_dim, and for NNN being the number of qubits to be simulated. There are four contributions to the peak memory consumption of emu-mps that will be discussed in the next sections:

  • the state
  • the baths
  • the Krylov space
  • temporary tensors

Contribution from the state

Section titled “Contribution from the state”

The quantum state is stored in MPS format (see here). At worst, the bond dimensions of the tensors in an MPS grow exponentially inwards as

2,4,8,16...,16,8,4,2 2,4,8,16...,16,8,4,2 2,4,8,16...,16,8,4,2

in which case an MPS will take more memory than a state vector. Let χ\chiχ denote the value of max_bond_dim. When χ<2N/2\chi<2^{N/2}χ<2N/2, the bond dimensions in the center all cap at that fixed value of max_bond_dim. Since each tensor in the MPS has 2 bonds of size at most χ\chiχ, and a physical index of size p=2p=2p=2 in the qubit (222-level system) case, where each element in the tensor takes s=16s=16s=16 bytes (222 888-byte floats to store a complex number), the memory consumption of the state reads

∣ψ∣<spNχ2=32Nχ2. |\psi| < spN\chi^2 = 32N\chi^2. ∣ψ∣<spNχ2=32Nχ2.

and more generally,

∣ψ∣<16pNχ2 |\psi| < 16pN\chi^2 ∣ψ∣<16pNχ2

for the qudit (p-level system) case.

Note that this is a strict over-estimation because the outer bonds in the MPS will be much smaller than χ\chiχ.

Contribution from the baths

Section titled “Contribution from the baths”

For the currently available solvers (TDVP and DMRG), for each qubit a left and a right bath tensor is stored. The bath tensors are used to compute an effective interaction between the 2-qubit subsystem being evolved, and the rest of the system (see here). Each of them has 3 indices. Two of them will have a size that depends on the state that is evolved, here upper bounded by the maximum allowed value χ\chiχ for the bond dimension. For the third, the size hhh will depend on the interaction type. In concrete, for each qubit, hhh will be the bond dimension of the MPO representation of the Hamiltonian. In summary, for the Rydberg Hamiltonian we expect that h=2+floor(n/2)h=2+\text{floor}(n/2)h=2+floor(n/2), and for the XY Hamiltonian that h=2+2floor(n/2)h=2+2\text{floor}(n/2)h=2+2floor(n/2), where in both cases n=min(i,N−i)n=\text{min}(i,N-i)n=min(i,N−i) for the bath associated with the qubit iii. The computation is slightly involved, but summing all the contributions leads to a total memory occupation of the baths:

∣bath∣<Nsχ2h=4χ2N(N+10) |\mathrm{bath}| < Ns\chi^2h = 4\chi^2N(N+10) ∣bath∣<Nsχ2h=4χ2N(N+10)

Note that the baths take up more memory than the state, always, and potentially much more. Furthermore, just as for the state this is a strict over-estimation, because it assumes all the bonds in the state are of size χ\chiχ.

Contribution from the Krylov space

Section titled “Contribution from the Krylov space”

The remainder of the memory consumption is to compute the time-evolution of qubit pairs in the TDVP or DMRG algorithms. This is done by contracting 2 tensors from the MPS together into a single 2-qubit tensor, and time-evolving (or minimizing) it by applying an effective Hamiltonian constructed from the baths and the Hamiltonian MPO. Each 2-qubit tensor has a size bounded by sp2χ2sp^2\chi^2sp2χ2, so the memory of the Krylov vectors used in the Lanczos algorithm reads

∣krylov∣≤ksp2χ2=64kχ2 |\mathrm{krylov}| \leq ksp^2\chi^2 = 64k\chi^2 ∣krylov∣≤ksp2χ2=64kχ2

where kkk is the value of max_krylov_dim. Recall that the default value of k=100k=100k=100 and if the Lanczos algorithm requires more Krylov vectors to converge to the tolerance, it will error, rather than exceed the above bound.

Contribution from temporary tensors

Section titled “Contribution from temporary tensors”

Finally, to compute the above Krylov vectors, the effective two-site Hamiltonian has to be applied to the previous Krylov vector to obtain the next one. The resulting tensor network contraction cannot be done in-place, so it has to store two intermediate results that get very large. The intermediate results take the most memory at the center qubit, where the bond dimension of the Hamiltonian becomes hhh, where

∣intermediate∣=2∗shp2χ2=128hχ2 |\mathrm{intermediate}| = 2*shp^2\chi^2 = 128h\chi^2 ∣intermediate∣=2∗shp2χ2=128hχ2

It should be noted that the value of hhh cited above assumes that all qubits in the system interact via a two-body term, which is technically true for the Rydberg interaction.

Benchmarking memory footprint

Section titled “Benchmarking memory footprint”

Putting all of this together, for the total memory consumption mmm of the program, we can write the following bound:

m(N,χ,k)=∣ψ∣+∣bath∣+∣krylov∣+∣intermediate∣<32Nχ2+4χ2N(N+10)+64∗k∗χ2+64(N+4)χ2=4χ2[N(N+34)+16k+64] m(N,\chi,k) = |\psi| + |\mathrm{bath}| + |\mathrm{krylov}| + |\mathrm{intermediate}| < 32N\chi^2 + 4\chi^2N(N+10) + 64*k*\chi^2 + 64(N+4)\chi^2 = 4\chi^2[N(N+34) + 16k + 64] m(N,χ,k)=∣ψ∣+∣bath∣+∣krylov∣+∣intermediate∣<32Nχ2+4χ2N(N+10)+64∗k∗χ2+64(N+4)χ2=4χ2[N(N+34)+16k+64]

Note that this estimate is pessimistic, since not all kkk Krylov vectors are likely to be needed, and not all tensors in ψ\psiψ and the baths have the maximum bond dimension ddd. On the other hand, the estimate for ∣intermediate∣|intermediate|∣intermediate∣ is likely to be accurate, since the bond dimension of χ\chiχ is probably attained at the center qubit.

Both TDVP and DMRG rely on the same bath construction and effective Hamiltonian machinery, so their memory requirements are expected to scale similarly with NNN and χ\chiχ.

To test the accuracy of the above memory estimations, we benchmarked the TDVP algorithm by fixing the bond dimension to a particular desired value. For different combinations of the number of atoms in a register NNN and the fixed bond dimension χ\chiχ, we collect the maximum resident size, or RSS, which is expected to capture the maximum memory needed to run the emulation. We plot the RSS in the following picture (left), as a function of the number of qubits and for different bond dimensions. Notice that, once the RSS is normalized by χ2\chi^2χ2, as suggested by our estimate above, all the points fall into the same functional dependency on the number of atoms. Moreover, as we plot the normalized function m(N,χ,k)/χ2m(N,\chi,k)/\chi^2m(N,χ,k)/χ2, for a reasonable estimate of the size of the Krylov subspace (k=30k=30k=30), it is clear that our upper bound on memory occupation can be reasonably trusted on a wide range of system sizes and bond dimensions.

Finally, having established an estimate for the memory consumption, it makes sense to explore what are the available regimes of qubits/bond dimension can be reached for a given hardware capability. Since all heavy simulations will be run on an NVIDIA A100 (on Pasqal's DGX cluster), we have 404040 GB of available memory. Although these results are shown for TDVP, a similar analysis could be performed for DMRG, and we expect the resulting memory scaling to be comparable.

Estimating the runtime of a simulation

Section titled “Estimating the runtime of a simulation”

Similarly to the previous section, here, we briefly estimate the complexity of both the two-site TDVP and DMRG algorithms we use to time evolve or minimize the state in a single pulse sequence step. As before, the two relevant computational steps are

  • Computing the baths
  • Applying the effective Hamiltonian

In both cases, it will boil down to an exercise in complexity estimation of tensor network contractions. For simplicity, as before, we will restrict to the worst case scenario in which the bond dimension χ\chiχ always take the maximum allowed value. Importantly, another significant contribution to the runtime can come from computing complex observables like two-point correlation functions, which is not included here.

Contribution from the baths

Section titled “Contribution from the baths”

Roughly, baths computation involves the represented tensor network contraction:

Each of these tensor multiplication takes respectively O(phχ3)O(ph\chi^3)O(phχ3), O(p2h2χ2)O(p^2h^2\chi^2)O(p2h2χ2), and O(phχ3)O(ph\chi^3)O(phχ3). In an all-to-all Rydberg interaction, we already argued that the bond dimension of the Hamiltonian MPO should scale as the number of atoms. Moreover, the left and right baths need to be computed roughly N times, thus the overall expected complexity is O(N2χ3)+O(N3χ2)O(N^2\chi^3) + O(N^3\chi^2)O(N2χ3)+O(N3χ2).

Contribution from the effective Hamiltonian

Section titled “Contribution from the effective Hamiltonian”

Applying the effective two-body Hamiltonian is slightly a more involved tensor network contraction:

In steps, it is composed by applying:

  • the left bath: O(p2hχ3)O(p^2h\chi^3)O(p2hχ3)
  • a two-body term coming form the MPO Hamiltonian: O(p4h2χ2)O(p^4h^2\chi^2)O(p4h2χ2)
  • the right bath: O(p2hχ3)O(p^2h\chi^3)O(p2hχ3)

As before, for an all-to-all Rydberg interaction we expect h∼Nh\sim Nh∼N. Moreover, the effective Hamiltonian application needs to be done kkk times, to build the appropriate Krylov subspace, and for every pair. Finally, to complete the time evolution or the energy minimization and bring back the tensors of the state into an MPS form, a final singular value decomposition is required. For every pair, this requires O(Nχ3)O(N\chi^3)O(Nχ3) to be done. Overall, the expected complexity is thus O(kN2χ3)+O(kN3χ2)+O(Nχ3)O(kN^2\chi^3) + O(kN^3\chi^2) + O(N\chi^3)O(kN2χ3)+O(kN3χ2)+O(Nχ3).

Benchmarking runtime

Section titled “Benchmarking runtime”

From the previous complexity estimations, we expect the computational complexity of both the two-site TDVP and DMRG algorithms to have two main contributions

Δt(N,χ,k)∼αN2χ3+βN3χ2\Delta t(N,\chi,k)\sim \alpha N^2\chi^3 + \beta N^3\chi^2Δt(N,χ,k)∼αN2χ3+βN3χ2

As previously discussed, both algorithms rely on the same bath construction and effective Hamiltonian machinery, so their scaling with the system size NNN and bond dimension χ\chiχ should be comparable.
